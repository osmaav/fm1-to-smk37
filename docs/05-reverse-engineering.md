# 05: Как были получены факты

Всё, изложенное в [01-hardware.md](01-hardware.md), было получено двумя способами. Сначала путём чтения
штатной прошивки SMK-37 Pro открытыми инструментами и сравнения с FM-1 и его хорошо задокументированными
открытыми прошивками. Затем проверкой результатов на реальном устройстве с самодельной прошивкой.
На этой странице описана методика, чтобы любой мог повторить её или распространить на будущую штатную
версию. Она не содержит кода производителя. Штатные файлы возьмите самостоятельно у M-Vave.

## 1. Инструменты

| Инструмент | Назначение |
|---|---|
| [jl-misctools](https://github.com/kagaimiq/jl-misctools) (kagaimiq) | распаковка пакета `.fwsc` на составные части |
| Компилятор JieLi pi32v2 (тот же, что используется в сборках прошивок) | `objdump` с точной декодировкой pi32v2 |
| [Ghidra](https://ghidra-sre.org/) с модулем [ghidra-jieli](https://github.com/kagaimiq/ghidra-jieli) | навигация, перекрёстные ссылки, представление декомпилятора |
| [jl-uboot-tool](https://github.com/kagaimiq/jl-uboot-tool) (kagaimiq) | чтение id flash и дампа flash через загрузчик mask-ROM |
| Заголовки SDK JieLi AC79 (`fw-AC79_AIoT_SDK`) | имена SFR, группы выводов SPI (`include_lib/driver/cpu/wl82/asm/spi.h`) |
| [FM-1-RE](https://github.com/AL-255/FM-1-RE), исходники Felucca и SLOOP | сторона FM-1: что делает каждый SFR и хелпер, уже названы |
| [jielie](https://github.com/kagaimiq/jielie) | семейства чипов, процесс загрузки, USB_KEY |

## 2. Распаковка штатного пакета

Используйте распаковщик «новой прошивки» из jl-misctools (`firmware/fwunpack_newfw.py`; аргументы см. в справке
инструмента). Нужны следующие части:

- `app.bin`: приложение, основной предмет анализа,
- `cfg_tool.bin` и `cfg`: конфигурация и ресурсы,
- `uboot.boot`: загрузчик второго этапа,
- `isd_config.ini`: конфигурация загрузки,
- `ota.bin`: загрузчик обновления,
- `flash.bin`: зашифрованный образ таким, каким он лежит в flash.

**Примечание:** штатный пакет v016 использует 36 блоков чередования вместо 20
([02-update-and-recovery.md](02-update-and-recovery.md), раздел 2.2). Если распаковщик предполагает 20,
каждая проверка CRC завершается ошибкой. Более старые версии (v011) используют 20.

Быстрые сравнения, которые уже многое говорят:

- Сравните `cmp` SPL, `isd_config.ini` и `ota.bin` пакета SMK с таковыми у FM-1. Они идентичны, значит,
  цепочка загрузки и механизм обновления общие.
- Сравните первые 16 КиБ обоих файлов `flash.bin`. Они тоже идентичны.
- Прочитайте таблицу областей (расшифрованный flash, начиная со смещения 0x4060). Она даёт карту flash SMK.
  Записи VM, BTIF, USRTRIM, USRFLASH и USR — **абсолютные** смещения flash. Не прибавляйте 0x4000.

## 3. Загрузка app по правильному адресу

`app.bin` выполняется на месте (XIP) по адресу **0x02000120**, а не 0x02000000. Чтобы убедиться в этом для любой
версии, найдите таблицу указателей на строки (например, названия длительностей нот) и проверьте, при каком базовом
адресе они попадают точно на начала строк. Также проверьте, что указатели функций в данных попадают на прологи
функций. Если анализируете по адресу 0x02000000, вычитайте 0x120 из каждого абсолютного указателя flash в коде.

Для дизассемблирования `objdump` из компилятора JieLi оберните сырой образ в минимальный ELF:

- ELF32, прямой порядок байтов, `e_machine` = 241 (pi32v2),
- один сегмент `PT_LOAD`: содержимое файла по виртуальному адресу 0x02000120, флаги R+X,
- дополнительно пустые сегменты для RAM (0x01C00000, 512 КиБ) и пространства SFR (0x00010000..0x00060000),
  чтобы ссылки разрешались в Ghidra.

Короткий скрипт с модулем Python `struct` делает это. Затем:

```sh
~/.jieli/toolchain/common/bin/objdump -d app.elf > app.dis
```

Загрузите тот же ELF в Ghidra с модулем ghidra-jieli для перекрёстных ссылок.

**Ловушки декодирования.** Модуль Ghidra неправильно декодирует несколько инструкций pi32v2. Сверяйте с
`objdump` всякий раз, когда важен смещение или регистр:

- загрузки и сохранения байта с регистром плюс смещение: смещение разбито по двум полубайтам, и декомпилятор
  может показать его в 16 раз больше реального (`+0x10d` там, где настоящий offset `+0x1d`). Регистр данных при
  побайтовом сохранении тоже может быть неверен.
- несколько логических операций и инструкций FPU отображаются как мусор или неверные мнемоники. Математика
  скорости удара пэдов в штатной прошивке — код FPU, и её удалось прочесть лишь частично.
- аннотации строк в выводе декомпилятора могут указывать не на ту строку. Разрешайте указатель сами.

## 4. Поиск каждой подсистемы

Ищите в дизассембле **адреса SFR** как непосредственные значения. Каждое периферийное устройство ведёт к своему
драйверу, а драйвер — к таблицам.

| Что искать | Периферия | К чему ведёт |
|---|---|---|
| `0x11E00` | SPI2 | сдвиг матрицы клавиш (CON, BAUD, адрес DMA, счётчик DMA), обработчик прерываний, порядок сканирования, вывод latch |
| `0x11D00` | SPI1 | драйвер ЖК-экрана (таблица инициализации, routines окна и заполнения) и кадр светодиодов пэдов |
| `0x51020` | `IOMAP_CON1` | какая группа выводов SPI у каждой шины. Сравнивайте биты со `spi.h` из SDK AC79. |
| `0x13100`, `0x13104` | SARADC | номера каналов, значение CON (тайминги), обработчик прерываний с конечным автоматом мультиплексора |
| `0x50000 + порт * 0x40` | порты GPIO | направление вывода, подтяжки, чтение входов (линии возврата матрицы), выходы (D/C, CS, latch) |
| `0x16A0C` | управление_pad'ами USB PHY | две общие шины светодиодов кнопок |
| `0x12100` | UART1 | настройка MIDI OUT и её вывод |

Хелперы GPIO — маленькие функции, вызываемые с id вывода и значением. Назовите их один раз, опираясь на прошивку
FM-1, где они уже известны: уровень выхода, направление, разрешение входа, подтяжка вверх, подтяжка вниз. После
этого каждый вызов настройки вывода становится читаемым.

Таблицы, найденные из кода, который их читает:

- **таблица контактов клавиш**: 37 пар кодов матрицы, читается циклом обработки клавиш по кадрам,
- **таблица кнопок**: 18 кодов матрицы, читается колбэком таймера кнопок,
- **таблица энкодеров**: 8 пар кодов, читается квадратурным декодером,
- **таблица светодиодов**: 19 записей «группа и бит», читается кодом мультиплексирования светодиодов,
- **карта пэдов**: 16 байт, фаза мультиплексора → индекс пэда, читается обработчиком АЦП,
- **карта цепи светодиодов**: пэд → позиция в цепи WS2812, читается установщиком цвета,
- **запись калибровки**: найдена по имени файла `usrtrim` и маркеру `trimdat`.

Строки тоже помогают. Строковые дескрипторы USB хранятся в UTF-16 («SMK-37 Pro Midi»). Текст интерфейса
калибровки («Scroll PITCH to bottom») называет колёса и их порядок. Запись идентификации `SMK-37 Pro_016`
находится рядом с кодом обновления.

## 5. О чём штатный код не расскажет

Статическое чтение даёт выводы, регистры и алгоритмы. Некоторые факты можно установить только на устройстве:

| Вопрос | Как был установлен |
|---|---|
| Корпус flash-памяти | `jl-uboot-tool` печатает JEDEC id при подключении в UBOOT (0xEB6014 на проверенном устройстве) |
| Физический порядок пэдов (какой мультиплексор — верхний ряд) | сырые показания пэдов из отладочной консоли при нажатии каждого пэда |
| Названия кнопок для id 6..17 | маска битов кнопок в консоли при нажатии каждой кнопки |
| Порядок и направление энкодеров | счётчики шагов по каждому энкодеру в консоли |
| Порядок цветов светодиодов | тестовый паттерн чистыми красным, зелёным и синим на известных пэдах |
| Диапазоны колёс и фейдеров | сырые показания в покое и на обоих концах хода |
| Тайминги АЦП | счётчики завершённых и пропущенных преобразований в консоли. С таймингами FM-1 почти все преобразования пропускались. |
| Путь обновления | установка самодельного пакета из штатного приложения, затем отправка мягкой клавиши для перехода в UBOOT |

Отладочная консоль — самый полезный одиночный инструмент для этого. Прошивки семейства Felucca имеют её поверх
USB-последовательного порта. Добавьте команду печати сырых входов рано в процессе переноса.

## 6. Основные правила

- Ведите заметки с уровнем уверенности для каждого факта: прочитано из кода с конкретными константами,
  выведено или предположено. Аппаратные тесты превращают выводы в факты.
- Публикуйте факты своими словами и таблицами. Не публикуйте бинарные файлы производителя, дампы,
  дизассемблерный листинг или декомпилированный код.
- Никогда не проверяйте путь записи flash на устройстве без проверенной полной резервной копии.
