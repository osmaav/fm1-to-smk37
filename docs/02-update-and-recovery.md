# 02: Обновление, резервное копирование, восстановление и возврат к штатной прошивке

SMK-37 и FM-1 разделяют механизм обновления: ту же библиотеку обновления в приложении, тот же
загрузчик обновлений (`ota.bin`, побайтово идентичный), тот же загрузчик второй ступени и тот же загрузчик mask-ROM. Всё,
что делают Felucca и SLOOP на FM-1, работает на SMK-37 после подгонки нескольких имён и размеров.

## 1. Как проходит обновление

1. **Проверка (работает штатное или пользовательское приложение).** Хост отправляет команду enter-upgrade по USB MIDI. Запущенное
   приложение выкачивает пакет с хоста небольшими чтениями и проверяет его. Если пакет принят, приложение копирует
   загрузчик обновлений из пакета в область staging во флеш и пишет **запись обновления**. Запись содержит
   адрес загрузчика и имя вида `ota-SMK-37 Pro_016`. После этого приложение сбрасывается.
2. **Запись (работает загрузчик обновлений).** Загрузчик второй ступени находит запись и запускает загрузчик. Загрузчик
   появляется на USB под именем из записи. Он снова выкачивает пакет и записывает область приложения.
   По завершении он удаляет свои записи и сбрасывается.
3. **Запуск.** Стартует новое приложение.

Если питание пропадёт на шаге 2, запись остаётся, и загрузчик снова запустится при следующем включении. Запустите
установщик ещё раз — он продолжит.

**Проверено на протестированном экземпляре:** штатное приложение SMK-37 Pro (v016) принимает пакет в стиле SLOOP, собранный для SMK,
и запускает из него пользовательский загрузчик обновлений.

## 2. Факты протокола

Все сообщения — SysEx по USB MIDI. Кадрованные сообщения выглядят так:

```
F0  pack7( 00 59  cmd  len(3 bytes, LE)  body  checksum )  F7
```

- `pack7` упаковывает 8-битные байты в 7-битные MIDI-данные, младшие биты первыми.
- Контрольная сумма — инвертированная 8-битная сумма тела сообщения.

| Сообщение | Байты (в линии) | Примечания |
|---|---|---|
| Запрос идентичности | `F0 00 32 45 00 00 00 40 7F F7` | Ответ: cmd `0x11`, 27-байтный текст идентичности с дополнением нулями |
| Вход в режим обновления | `F0 22 24 35 7F F7` | Одна и та же команда на FM-1 и SMK-37 |
| Запрос чтения (устройство → хост) | cmd `0x30`: флаги, адрес (4 байта), длина (3 байта) | Устройство выкачивает пакет. Хост отвечает cmd `0x30` с тем же адресом и данными. |
| Рукопожатие | устройство читает 8 байт по `0xE0000000` (шаг проверки) и `0xF0000000` (шаг записи) | Хост отвечает `success\0` |
| Мягкий ключ UBOOT | `F0 22 24 35 7D F7` | Понимается загрузчиком обновлений и приложением Felucca/SLOOP, но **не** штатным приложением. Перезапускает чип в загрузчик mask-ROM. |

Штатное приложение сбрасывается после шага проверки, даже если рукопожатие не удалось. Загрузчик SLOOP строже.

### 2.1 Идентичности

| Кто отвечает | Текст идентичности | Примечания |
|---|---|---|
| Штатное приложение | `SMK-37 Pro_016` | на FM-1 — `FM-1_015` |
| Штатный загрузчик обновлений | `ota-SMK-37 Pro_016` | берётся из записи обновления |
| Пользовательское приложение (эталонный порт) | `SMK-37 Pro_900`, релизные сборки `SMK-37 Pro_9XY` | |
| Пользовательский загрузчик обновлений | `ota-SMK-37 Pro_900` | |
| Пользовательский экран восстановления | `SMK-37 Pro_000` | |

Хосты сравнивают модели по тексту до подчёркивания (`SMK-37 Pro`). Обычный шаблон `([^_]+)_(\d+)` допускает
пробел. Установщики должны также принимать имена MIDI-портов, содержащие `SMK`. Штатный порт называется
"SMK-37 Pro ...", и фильтр порта FM-1 его отвергает.

**Имя записи обновления.** Когда пользовательское приложение передаёт управление загрузчику, оно само пишет запись. На SMK нужно
писать `ota-SMK-37 Pro_016` (18 байт, дополнение нулями до смещения +0x27 записи), а не `ota-FM-1_015`.
Загрузчик на обоих устройствах идентичен и берёт своё USB-имя из этой записи. С неверным именем инструмент M-Vave
может не распознать официальный загрузчик при возврате к штатной прошивке.

### 2.2 Контейнер пакета `.fwsc`

Пакет — это образ JieLi формата «UFW» (заголовок, `flash.bin`, `ota.bin`, ресурсы) со вплетённой идентичностью:

- Начало файла разбито на **блоки по 0x30 байт**. Байты 0x00..0x2E каждого блока — данные.
  Байт 0x2F — маркер.
- Для блока `i` маркер равен `identity[i] + i + 1` (mod 256), пока символы идентичности не кончатся, и
  `0x7D` после этого.
- Образ, который устройство читает во время обновления, — файл со всеми удалёнными байтами-маркерами.

| Пакет | Блоков |
|---|---|
| Штатный FM-1, Felucca, SLOOP | 20 |
| **Штатный SMK-37 Pro v016** | **36** (14 символов идентичности + 22 x `0x7D`) |
| Штатный SMK-37 Pro v011 | 20 |

Установщик, предполагающий 20 блоков, читает пакет v016 со смещением на 16 байт, и каждая CRC не сходится. Надёжное
правило: считать блоки, пока `i < 20` или маркер равен `0x7D`. Затем проверить CRC `flash.bin` и `ota.bin`
в результате. Если они не сходятся, откатиться к 20 блокам.

**Особенность.** В штатных пакетах сохранённые CRC маленьких ресурсных файлов (USR, `isd_config.ini`,
`script.ver`, `blimit.bin`) не совпадают с отдаваемыми байтами. Совпадают только `flash.bin` и `ota.bin`. Установщик,
проверяющий каждый файл, отвергнет любой штатный пакет. Проверяйте только эти два.

### 2.3 Что записывает пакет

Пакет для SMK должен нести таблицу областей SMK (см. [01-hardware.md](01-hardware.md), раздел 2):
размер PRCT `0x9D000`, VM `0x9D000`/`0x23000`, BTIF `0xC0000`, USRTRIM `0xC1000`, USRFLASH `0xC2000`/`0x29000`
и USR `0xF4000`/`0xA000`, со штатными флагами. Образ приложения должен помещаться в слот приложения. Эталонный порт линкуется
с длиной XIP `0x97400` (размер штатного приложения).

## 3. Полное резервное копирование флеш (сделайте это первым делом)

Понадобятся:

- [jl-uboot-tool](https://github.com/kagaimiq/jl-uboot-tool) (Python 3). Он общается с загрузчиком mask-ROM через
  необработанные SCSI-команды, поэтому нужны root на Linux и повышенная оболочка на Windows.
- Пользовательский пакет SMK, например сборка эталонного порта.
- Хостовый инструмент, способный выполнить шаг проверки обновления и затем отправить одно сообщение SysEx. Установщики
  Felucca и SLOOP содержат все строительные блоки: загрузку пакета, поиск устройства и шаг проверки.

### 3.1 Метод A: до установки чего-либо (предпочтительно)

1. Подключите SMK-37 по USB и закройте все прочие программы, использующие его MIDI-порт.
2. Выполните **только шаг проверки** с пользовательским пакетом: запрос идентичности, вход в обновление, отдача чтений. Штатное
   приложение принимает пакет и сбрасывается в пользовательский загрузчик обновлений. Его идентичность теперь `ota-SMK-37 Pro_9xx`.
   К этому моменту в области приложения ничего не перезаписано.
3. Отправьте загрузчику мягкий ключ UBOOT `F0 22 24 35 7D F7`. Клавиатура заново появляется на USB как устройство
   USB mass-storage с именем **`WL82 UBOOT1.00`**. **Проверено на протестированном экземпляре.**
4. Найдите устройство: `/dev/sgN` на Linux или `\\.\PhysicalDriveN` на Windows (диск с именем `WL82 UBOOT`).
5. Прочитайте всю флеш дважды:

   ```
   python3 jluboottool.py --device <device> --chip wl82 "read 0 0x100000 smk37-dump-1.bin"
   python3 jluboottool.py --device <device> --chip wl82 "read 0 0x100000 smk37-dump-2.bin"
   ```

   Инструмент печатает id флеш при подключении. Запишите его (протестированный экземпляр сообщает `0xeb6014`).
6. Проверьте дампы:
   - оба ровно 1048576 байт,
   - у обоих одинаковый SHA-256,
   - по смещению `0xC1224` лежат 7 символов `trimdat`.

   Если любая проверка не прошла — не доверяйте дампу. Читайте заново.
7. Храните дамп минимум в двух местах. Диапазоны `0xC0000-0xC1FFF` (сопряжение Bluetooth и калибровка) и
   `0xFF000-0xFFFFF` (key_mac) уникальны для вашего экземпляра.
8. Перезапустите питание клавиатуры. Она вернётся в режим обновления пользовательского загрузчика, потому что запись обновления
   ещё на месте. Либо завершите установку пользовательского пакета, либо установите штатный пакет, чтобы остаться на штатной.

### 3.2 Метод B: после установки пользовательской прошивки

Прошивка на базе SLOOP может сама войти в загрузчик mask-ROM: удерживайте OCTAVE- и OCTAVE+ 5 секунд
при остановленном секвенсоре, или введите `uboot yes` в USB-последовательной консоли. Затем выполните шаги 4–8 выше.

Дамп, полученный так, больше не содержит штатную область приложения, но всё ещё содержит уникальные для экземпляра диапазоны,
потому что корректный порт никогда их не записывает. Штатную область приложения всегда можно восстановить из штатного пакета.

## 4. Установка пользовательской прошивки

1. Соберите пакет для SMK (см. [03-porting-steps.md](03-porting-steps.md)). Эталонная сборка пишет
   `build/sloop-smk37.fwsc`, идентичность `SMK-37 Pro_900`.
2. Установите собственным установщиком прошивки (командная строка или веб). Установщик должен:
   - принимать MIDI-порты с именами `SMK...`,
   - принимать модель `SMK-37 Pro` и отвергать пакет для другой модели,
   - принимать идентичность загрузчика `ota-SMK-37 Pro_9xx`.
3. Не трогайте клавиатуру, пока она не перезапустится в новой прошивке.

Прервалось? Перезапустите питание и запустите установщик снова. Загрузчик продолжит.

Первая загрузка: порт проверяет тег владельца хранилища (`0xAF000`). Данные без тега порта принадлежат другой прошивке,
поэтому очищаются: с `FELUCCA_DATA_UNTAGGED_OK 0` это включает настройки штатной прошивки (`0x9D000-0xAEFFF`
и `0xB0000`). Калибровка, данные Bluetooth и штатные ресурсы не затрагиваются, и штатная прошивка
перестроит свои настройки после возврата к штатной. Предупредите владельца перед первой установкой.

## 5. Восстановление

От лёгкого к тяжёлому:

| Ситуация | Что делать |
|---|---|
| Установка прервана (пропало питание, кабель) | Перезапустите питание. Пользовательский загрузчик стартует снова. Запустите установщик ещё раз. |
| Новая прошивка падает при загрузке | Прошивка на базе SLOOP считает неудачные загрузки. После двух открывается USB-экран восстановления (идентичность `SMK-37 Pro_000`), принимающий новый пакет. После третьей — переход в загрузчик mask-ROM. |
| Прошивка работает, но нужен загрузчик mask-ROM | Удерживайте OCTAVE- + OCTAVE+ 5 с при остановленном секвенсоре, или используйте консольную команду `uboot yes`. |
| Ничего не отвечает по USB MIDI | Если загрузчик второй ступени или заголовок приложения повреждены, mask ROM сам входит в UBOOT. Если нет — используйте JieLi-донгл USB_KEY (RP2040, который импульсит загрузочный ключ на линиях данных USB при подаче питания): [FM-1 Transporter](https://github.com/kurogedelic/FM-1-transporter), [MvaveFM1Unbricker](https://github.com/Quixotic7/MvaveFM1Unbricker). Они созданы для FM-1. У SMK-37 Pro тот же чип и загрузочная ПЗУ, но донгл на нём ещё не опробован. |

### 5.1 Запись флеш в загрузчике mask-ROM

`jl-uboot-tool` умеет стирать и записывать любой диапазон. Правила:

- **Никогда не пишите `0x0000-0x3FFF`, `0xC0000-0xC1FFF` или `0xFF000-0xFFFFF`.** Восстанавливайте их только из собственного
  дампа и только если они повреждены.
- Работайте целыми 4 КиБ секторами. Сотрите диапазон, запишите его, затем прочитайте обратно и сравните.
- Чтобы вернуть штатное приложение, запишите диапазон `0x4000-0x9CFFF` из вашего дампа метода A. Без такого дампа
  вместо этого штатно установите штатный пакет. `flash.bin` пакета — это зашифрованный образ таким, каким он лежит
  во флеш.

```
python3 jluboottool.py --device <device> --chip wl82 "erase 0x4000 0x99000"
python3 jluboottool.py --device <device> --chip wl82 "write 0x4000 app-area.bin"
python3 jluboottool.py --device <device> --chip wl82 "read 0x4000 0x99000 check.bin"
```

`app-area.bin` — это байтовый диапазон `0x4000..0x9CFFF`, вырезанный из вашего дампа. Выход из UBOOT — перезапуск питания.

## 6. Возврат к штатной прошивке

1. Получите официальный пакет прошивки для вашей модели у M-Vave. Сообщество в репозитории
   [smk-37-pro-docs](https://github.com/jonathaslacerda/smk-37-pro-docs) хранит историю штатных версий.
2. Установите его так же, как любой пакет:
   - собственным обновлятором M-Vave, или
   - установщиком стиля Felucca/SLOOP, понимающим 36-блоковый контейнер (раздел 2.2). Такие установщики
     отвергают пакеты без собственного маркера загрузчика, если не принудить (`--force` в консольном
     установщике SLOOP).
3. Штатная прошивка загрузится с целой вашей калибровкой, потому что пользовательская прошивка никогда не писала USRTRIM.

**Оставленные данные.** Эталонный порт хранит пользовательские сэмплы в диапазоне USRFLASH (`0xC2000-0xE9FFF`), а свои
проекты — в VM (`0x9D000-0xBFFFF`). После возврата штатная прошивка находит там чужие данные. Пока неизвестно,
форматирует ли она эти области сама. Для чистого состояния запишите эти диапазоны обратно из дампа метода A
в загрузчике mask-ROM или сотрите их в `0xFF`.

Когда прошивка на базе SLOOP устанавливает штатный пакет, она принимает официальный загрузчик только если первые
16 КиБ пакета равны началу флеш устройства. Пользовательская прошивка никогда не пишет этот диапазон, поэтому проверка проходит.
Она также пишет штатное имя записи обновления (`ota-SMK-37 Pro_016`), чтобы официальный загрузчик появился под
именем, которое ждут инструменты M-Vave.
