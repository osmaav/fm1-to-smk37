# 08: Подводные камни

То, что шло не так в прежних переносах, и способы исправления. Проверяйте этот список перед шагом 1 и снова
перед релизом.

## Флеш и данные

| Подводный камень | Исправление |
|---|---|
| Форк перенёс свою карту флеша (раскладка Melodee 1.0 пересекает защищённые диапазоны SMK). | Переработайте раскладку внутри разрешённых окон (хранилище `0x9D000-0xBAFFF`, сэмплы `0xC2000-0xE9FFF`). Никогда не пишите в `0x0-0x3FFF`, `0xC0000-0xC1FFF`, `0xF4000-0xFDFFF` и всё начиная с `0xFF000`. Проверяйте адрес конца каждого блока утверждениями. |
| Две прошивки после переключения читают данные флеша друг друга и ведут себя неверно. | Каждая прошивка получает своё семейство данных / тег владельца (`FELUCCA_DATA_FAMILY` в эталонной серии). Хранилище с другим тегом считается пустым. |
| Настройки FM-1 на `0xFC000`/`0xFD000` попадают в защищённую область USR у SMK (`0xF4000-0xFDFFF`). | Перенесите их в окно хранилища. Проверяйте каждый объект на защищённые диапазоны по его перечислению `OBJ_*`, а не только по адресам, которые найдёт grep. |
| Два объекта делят одну пару секторов A/B (различаются типом записи), поэтому список адресов показывает один объект. | Оставьте их делящими пару под своими типами или дайте каждому свою пару. Дополнительные объекты идут в `0xB1000-0xBAFFF`. |
| `_Static_assert(OBJ_COUNT == 10u)` слоя Felucca останавливает сборку. | Так и задумано: у форка появился новый объект. Дайте ему место, затем расширьте утверждение и тест карты флеша. |
| Тест тега владельца падает после смены семейства. | `tests/smk_owner_test.c` может жёстко прописывать `SMK37DATAFELUCCA`; возьмите и там семейство из `FELUCCA_DATA_FAMILY`. 7-буквенное семейство заполняет 16-байтовый тег без NUL: сравнивайте 16 байт, а не `sizeof` (17). |
| Название проекта 8 букв и больше (GHOULBOX); семейство принимает 1..7. | Сократите его (`GHOULBX`). |
| Форк хранит свои данные в «неиспользуемых» байтах настроек, которые позже применяет вышестоящий релиз (песня felucca-rainbow в `favorites.factory[14..15]`, байт PRESETS LIST у Felucca 1.2). | Делите семейство данных вышестоящей прошивки, только если раскладки настроек совпадают побайтово; иначе дайте переносу своё семейство. |
| Вишпикивание слоя Felucca на старый форк: половина FM-1 в `fm1_flash_map.h` несёт `FL_VBANK` из 1.4.1, и диапазон хранилища FM-1 растёт. | Копируйте значения FM-1 из собственного `fm1_flash.h` форка в `fm1_flash_map.h`, никогда из слоя. Проверяйте хэши FM-1. |
| Первая загрузка стирает настройки штатной прошивки (данные без тега). | Ожидается при `FELUCCA_DATA_UNTAGGED_OK 0`; калибровка и путь возврата в безопасности. Предупредите владельца перед первой установкой. |
| Новой настройке или калибровке нужно место, но структура настроек читается по фиксированным смещениям (веб-редактор SLOOP правит байты 48..83), а старые прошивки проверяют длину объекта. | Используйте свободные биты / запасные байты (TRS MIDI OUT: бит 31 слова настроек, 1 = OFF; BEND RANGE: запасной байт части MIDI, 0 = по умолчанию) или собственный маленький объект (калибровка колёс). Избегайте `0xB0000` (данные VM штатной прошивки; хранилище без тега сохраняет их); дополнительные — с `0xB1000`. При смене тега владельца стирайте и дополнительные сектора. |
| Слияние вышестоящих изменений переиспользует бит настроек, уже занятый переносом (канал MIDI у SLOOP 2.6 против битов BOOT LOGO у Snoop37). | После каждого слияния сравнивайте структуру настроек и её битовые маски. Перенесите биты переноса в свободное место и мигрируйте старые значения. |

## Идентичность, модели и установщики

| Подводный камень | Исправление |
|---|---|
| SMK выпускается как SMK-37 Pro, SMK-37 Elite и MKE-P37; штатный обновлениятор принимает только модель своего устройства. | Собирайте по одному пакету на модель: `BOARD=smk37 MODEL=elite sh build.sh` (`pro`, `elite` или `mke`). Каждый сообщает имя своей модели, чтобы штатный обновлениятор мог восстановить заводскую прошивку. |
| Старый слой (Felucca 1.5.1) не знает `MODEL`; `MODEL=elite` молча игнорируется, и собирается пакет Pro. | Используйте текущий слой (Felucca 1.6 или SLOOP 2.6), чей коммит по моделям добавляет `SMK_MODEL`. |
| Коммит по модели, взятый из другого переноса, жёстко прописывает имена того переноса (семейство Rainbow по умолчанию и основа `rainbow37`). | Замените их в build.py, build.sh, BUILDING.md, run_tests.sh и `tests/smk_owner_test.c` на имена проекта: `<project>-smk37`. |
| Имя Starrykey 37 Play, `STARRYKEY-37 PLAY` плюс версия, занимает 21 символ; 20-блочная идентичность пакета вмещает 20. | Используйте для него сборку SMK-37 Pro. Установщики принимают пакет любой модели SMK на любой модели SMK (никогда FM-1 на SMK или обратно). Читайте идентичность штатного пакета V016 за пределами 20 блоков (он занимает 21, затем неиспользуемые маркеры 0x7D) и идентичность устройства целиком (байты 6..32). |
| Переносы, выпущенные как переименованные продукты («xxx37») с указанием портера на экране загрузки, выглядят как присвоение чужой работы. | Сборка SMK-37 сохраняет имя, логотип и загрузку проекта; пакеты `<project>-smk37[-elite|-mke].fwsc`; цель — PR наверх (AGENTS.md, «Цель»). |
| Установщик не находит клавиатуру, работающую под другим переносом. | Фильтры имён переносов должны включать USB-имя каждой прошивки. Добавьте своё в поставляемые установщики. |
| Ответ идентичности другой прошивки обрывает текст раньше времени; сравнения строк падают. | Разбирайте идентичности до первого NUL-байта. |
| Windows показывает MIDI-порты как `MIDIIN2 (name)` и подобные. | Сравнивайте имена портов по подстроке, без учёта регистра. |
| `resume()` установщика (устройство уже в режиме обновления) писал любой загрузчик, тогда как `install()` проверял модель: при принятых загрузчиках SMK устройство SMK в режиме обновления могло получить пакет FM-1 (найдено в ревью SLOOP; есть и у форков Felucca 1.1.5). | `resume()` принимает идентичность пакета и проверяет модель загрузчика по правилу `install()` (равенство или правило одной клавиатуры); без идентичности ничего не пишет. Все вызывающие стороны передают её. Тестируйте оба случая: неверная модель и отсутствие идентичности — ничего не обслуживается. Эталон: `web/fm1ota.js` слоя и его тесты (AGENTS.md, шаг 8). |
| Форк изменил сам `resume()` (GHOULBOX: 4-й аргумент `waitMs`, путь перезагрузки); эталонный файл и версия форка конфликтуют. | Возьмите эталонный файл, верните части форка как опции (`opts.waitMs`), переведите всех вызывающих и тесты. Фейковое устройство тестового стенда тоже различается по форкам. |

## Сборка и тесты

| Подводный камень | Исправление |
|---|---|
| Клонирование в Windows превращает LF в CRLF; патчи перестают применяться, хэши меняются. | `git clone -c core.autocrlf=false URL` (после `clone`, чтобы сохранилось) или `git config core.autocrlf false` и повторный checkout. `git -c core.autocrlf=false clone` не сохраняется. Проверка: `git config --local core.autocrlf` печатает `false`. |
| `__DATE__` в прошивке делает сборки разными изо дня в день. JieLi clang игнорирует `SOURCE_DATE_EPOCH`, а фиксированное определение добавило бы флаг в сборку FM-1. | Сравнивайте в тот же день, что и базлайн, или пересоберите базлайн из базового коммита в день сравнения (`git worktree add ../fm1-base <base>`), или запустите обе сборки под `faketime`. |
| Тесты падают после сборки SMK. | Обе платы пишут одни и те же промежуточные файлы в `build/`. Соберите SMK, скопируйте его пакет, соберите FM-1, затем запускайте тесты. |
| Большой набор тестов падает, не называя упавшую часть. | `grep -n "FAIL\|OVER BUDGET"` по логу или заставьте раннер печатать имя каждого набора. |
| Инструменты шрифтов и изображений падают с `ImageFont has no attribute 'Layout'`. | Нужен Pillow с raqm; дистрибутивные пакеты часто слишком старые. `python3 -m venv ~/.venv-fw && ~/.venv-fw/bin/pip install Pillow fonttools`; проверьте `features.check('raqm')`. |
| Команды из Git Bash в WSL теряют переменные `$`. | Запускайте сборки и тесты внутри WSL; длинные команды помещайте в скрипт и запускайте `wsl bash script.sh`. |
| Собственный агентский файл форка велит автоматически мержить или пушить. | Правила комплекта важнее: работайте в `smk37`, владелец мержит и пушит. |
| PR наверх правил живой сайт: `docs/` генерируется из `web/` через `make_site.py` и публикуется сопровождающим (найдено в ревью SLOOP). | PR меняет только исходники. Оставьте `docs/` и другие генерируемые/публикуемые каталоги сборке сопровождающего. Кладите документацию SMK на верхний уровень (`SMK37.md`) или иное место вне публикуемого дерева. |
| Смерженный перенос сломал браузерный эмулятор сопровождающего (`web/emu/build.sh`): общие исходники использовали `FL_JEDEC_OK` и `FM1_OCT_BOTH` из `hal/`, которые эмулятор не включает (найдено в слиянии MAKU, откачено). | Перед PR собирайте каждую цель репозитория: прошивку, эмулятор/симулятор и то, что запускает CI. Определяйте новые общие макросы там, где их видит и эмулятор (например, в `web/emu/*.c` со значениями FM-1). |
| `web/emu/build.sh`: Permission denied в свежем клоне. | Запускайте через `sh web/emu/build.sh`. |
| Веб-тесты падают на Windows node (удвоенные пути с буквой диска из `new URL(".", import.meta.url).pathname`, двоеточие диска в аргументах `path:key`) или пропускаются. | Запускайте их в WSL с node в PATH там (из emsdk: `. ~/emsdk/emsdk_env.sh`). |
| Тестовый файл, записанный через heredoc оболочки, получил настоящие байты NUL и перевода строки там, где в исходнике C были `\0` и `\n`. | Проверяйте генерируемые исходники на управляющие байты перед коммитом (`grep -P '[\x00-\x08]'`). |
| Хостовые тесты на glibc падают на `clock_gettime` и подобных с `-std=c99`. | `CC='cc -D_DEFAULT_SOURCE' sh tests/run_tests.sh` (некоторым форкам нужен `-D_GNU_SOURCE`, другим ничего). |

## Код форка

| Подводный камень | Исправление |
|---|---|
| У форка собственный stub загрузки перед приложением (ChoralRoot: `firmware/stub`, маркер коммита, docs/BOOT-SAFETY.md). Он несёт свои копии последовательностей регистров FM-1: прижимает PA2 к нулю (шина матрицы FM-1) и бит-бэнгом выдаёт 16-битное слово 595. На SMK PA2 — строка матрицы. | Дайте stub вариант SMK под `BOARD_SMK37`: никогда не трогать PA2 (шины на SMK нет); сдвигать 32 бита вручную в порядке SPI DMA (байты слова little-endian, каждый msb первым); сначала сбросить назначение пинов SPI2 (тёплый сброс сохраняет назначенное приложением); OCTAVE- — колонка 6, OCTAVE+ — колонка 3, обе на строке PH8; staged-загрузчик на 0xBB000 и обычное окно с 0x9D000. Слот app.bin, тело и маркер оставьте на местах FM-1 (PRCT у SMK больше, остальное остаётся 0xFF). Запись обновления stub называет модель: по одному локу stub на модель. Проверьте загрузку на устройстве: финальная строка идентичности установщика, затем строка stub из `--debug` (сэмплы, регистр PH). |
| Форк хранит гораздо больше Felucca (ChoralRoot: 19 объектов и 20 цикловых секторов), а в окне хранилища 0x9D000-0xBAFFF всего 30 секторов. | Форк без сэмплов может использовать USRFLASH (0xC2000-0xE9FFF, `FL_SMP`) для крупных объектов (банки, слоты циклов). Ведите один список всех областей данных и используйте его и при смене владельца, и в собственном меню «стереть данные» прошивки; тег владельца остаётся на 0xAF000 вне этого списка. |
| Код светодиодов форка строит битмапы колонок из позиций `FM1_KEYMAP` с идентификаторами FM-1 (кнопки 0..13, клавиши 14 + k). Идентификаторы кнопок SMK доходят до 17 и сталкиваются с идентификаторами клавиш. | Сохраните компоновку форка и дайте SMK плоское пространство идентификаторов (id / 8, id % 8) со сдвинутыми вверх идентификаторами клавиш (ChoralRoot: `CU_LK(k)`); одна выходная функция SMK в конце считывает уровни обратно для светодиодов кнопок и пэдов. |
| Потеря побайтовой идентичности из «равной» константы: `id < NB` (int enum), заменённое на `FM1_NBTN` (`14u`), меняет значность сравнения и может изменить код. | Оберните старое выражение макросом, разворачиваемым ровно в старый текст на FM-1 (`#define PANEL_NBTN NB`) и в значение SMK под `BOARD_SMK37`. Проверяйте хэши FM-1 после каждой области. |
| Установщики форка классифицируют запущенную прошивку (ChoralRoot: `classify_firmware` / `classifyFirmware`): любая идентичность не `FM-1_...` отвергается как неизвестная, поэтому SMK-порт нельзя установить поверх собственной прошивки SMK или другого переноса. | Добавьте строки SMK в обе таблицы (штатные `SMK-37 Pro_0NN` и т.п., 7xx / 9xx переносов, собственный INFO-текст форка; `SMK-37_9NN` отвергается как `other`), держите две таблицы равными (собственный тест форка Python-против-JS) и применяйте поведение SMK-установщика на каждом пути (правило модели, только наш загрузчик, длинные идентичности). |
| Хостовым инструментам форка нужен Python новее, чем по умолчанию в WSL (`gen_tables.py` ChoralRoot использует `math.exp2`, Python 3.11). | Venv из `uv` с Python 3.12 и Pillow / fontTools; сравнивайте базу и новое в одной среде. |
| Собственный режим форка заменяет `ui_input()`, `ui_leds()` и `ui_draw()` (игрушка felucca-rainbow); пэды, фейдеры, колёса, крайние клавиши и дополнительные кнопки там ничего не делают. | Greпом найдите всех читателей `fm1_in`, `panel_enc`, `fm1_input_edges` и всех писателей `fm1_led*`; подключите дополнения SMK в каждый режим, владеющий кадром. |
| Цикл `for (id = 0; id < 14u; id++)` по кнопкам FM-1: на SMK FX, SEQ, PLAY и REC (идентификаторы 14..17) мертвы. | Используйте `FM1_NBTN` (14 на FM-1, 18 на SMK). Greпом ищите в форках `14u`, `27u` и `14u + k`. |
| Код светодиодов форка с `uint8_t nl[FM1_NCOL]` и идентификаторами светодиодов клавиш `14u + k` на SMK пишет за границы (`FM1_NCOL` равно 16, идентификаторы светодиодов доходят до 63). | Напишите SMK-версию этой функции светодиодов (кнопки и пэды), а не просто пересоберите. |
| Форк добавил собственные комбинации включения и проверки JEDEC со значениями FM-1 (GHOULBOX: USB RESCUE как `(buttons & 3u) == 1u`, JEDEC `== 0x856014u`); `FM1_OCT_BOTH` / `FL_JEDEC_OK` слоя покрывают только места Felucca. | Greпом найдите `buttons & 3u`, `& 1u) ==`, `0x856014` и исправьте каждое (OCTAVE- на SMK — кнопка 4). |
| Код форка читает поле `fm1_in`, отсутствующее у ввода SMK (крэнк GHOULBOX: `enc_dfr`), или считает во фреймах FM-1 (909/с; у SMK — 625/с). | Добавьте поле в `smk_input.h`; greпом ищите константы временнóго базиса кадра. |
| Форк отрефакторил `key_on` (GHOULBOX: `key_on_to(t, note, chord, chn)`, без индекса клавиши); `key_vel(k)` слоя в `key_on(k)` больше не подходит. | Вызывающая сторона передаёт velocity сама. |
| Крайние клавиши идут прямо в `input_on` / `input_off`: без аккорда, залипания или сплита форка. | Направьте их через помощники key_on / key_off форка (собственные буферы аккордов, 10 слотов); добавьте их в функции, перечисляющие зажатые клавиши. |
| Экранные «K1»..«K4» в прошивке FM-1 означают KNOB 1..4 (строки меню HOME у Snoop37); на SMK эти ручки — K5..K8 (K1..K4 — MASTER, SELECT, ALGORITHM, PRESETS). | Исправляйте каждую такую метку под `BOARD_SMK37` (строки меню, подсказки, строки помощи, `SMK37.md`); greпом ищите UI-строки и метки вида `'1' + i`. Также «KNOB 1»..«KNOB 4» аппаратной калибровки (Snoop37: K2 SELECT, K3 ALGORITHM, K4 PRESETS, K5..K8). Сборка FM-1 остаётся побайтово идентичной. |
| Потолок громкости, применённый к мастер-уровню после `master_poll`, оставляет виртуальный потенциометр K1 работать за потолком; убавление тогда ничего не делает много щелчков. | Ограничивайте и виртуальный потенциометр (`smk_master`) значением потолка потенциометра (в Felucca master = pot^2 / 256). |

## Аппаратная часть

| Подводный камень | Исправление |
|---|---|
| Новые WS2812 требуют более длинного сброса, чем посылает штатная прошивка; сбой сдвигает цепочку, и пэд зажигает соседа. | Посылайте длинный сброс (около 250 байт нулей) перед каждым кадром светодиодов пэдов. |
| Документация, комментарии и тексты консоли расходились, какой ряд какой. | Проверено на устройстве: верхний ряд = аппаратные пэды 0..7, нижний = 8..15, один индекс для ударов и светодиодов ([01-hardware.md](01-hardware.md), 6.3).
